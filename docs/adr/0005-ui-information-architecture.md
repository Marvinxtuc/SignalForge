# ADR 0005: UI Information Architecture

## Context

The UI must help the user decide quickly whether an actionable opportunity exists.

## Decision

Prioritize Signal Inbox, then Dashboard, Opportunity Board, Logs, and Settings. The UI must be dense, readable, calm, and evidence-first.

## Alternatives

- Marketing homepage: rejected for MVP.
- BI dashboard-first layout: rejected because review workflow starts from evidence.

## Consequences

Signal Inbox must make high-value signals visible, keep Open Source actions obvious, and preserve source_url for verification.

## Rollback / Revisit condition

Revisit if user review shows opportunities are easier to evaluate from board-level summaries than from signal-level evidence.
